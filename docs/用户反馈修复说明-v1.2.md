# HTML2APK v1.2.0 · 用户反馈修复说明

> 这份文档可以直接发给反馈问题的用户。结论先说：这次反馈的 5 类问题，
> 根因都在「产物壳」和「构建引擎」的实现上，不是大家页面写错了。
> **必须用新版 HTML2APK 重新打包一次**，旧 APK 不会自动变好。

---

## 1. “我想让文件保存 JSON，打包前网页里可以，打包后就不行”

### 原因
旧壳只把页面塞进 WebView，没有实现任何下载/保存能力：

- `<a download>` 点击后，WebView 不知道把 Blob 写到哪里；
- `blob:` / `data:` URL 只存在于页面进程内，`DownloadListener` 拿不到内容；
- `showSaveFilePicker()`（File System Access API）在 WebView 里本来就不存在；
- 旧壳用 `file://` 加载页面，浏览器对本地文件的下载限制更严格。

所以在浏览器里点“保存”会弹下载，在 APK 里点就是“没反应”。

### 修复（v1.2.0）
新壳内置了一个下载/保存层：

- 拦截 `<a download>`、`blob:`、`data:` 链接（包括 JS 里 `a.click()` 的写法）；
- 页面里生成的内容按 256KB 分块，通过 JS Bridge 交给原生；
- Android 10+ 用 MediaStore 写入 **`Download/HTML2APK/`**，不需要存储权限；
- Android 7–9 自动申请写存储权限，失败则保存到 App 专属目录并提示；
- 补齐了 `showSaveFilePicker()` / `showOpenFilePicker()` 的兼容层；
- 页面也可以主动调用：
  ```js
  HT2A_WEB.saveJSON('data.json', {a: 1});          // 推荐
  HT2A_WEB.saveText('note.txt', 'hello', 'text/plain');
  HT2A_WEB.saveBlob(blob, 'file.bin');
  ```

### 你需要做什么
1. 安装新版 HTML2APK；
2. **重新构建**原来的 HTML/文件夹（旧 APK 不会获得新壳）；
3. 再点保存按钮，文件应在 `下载/HTML2APK/`（部分文件管理器显示为 `Download/HTML2APK`）。

> 如果页面用的是 `showSaveFilePicker`，新壳会直接保存到下载目录，
> 不会弹“选择保存位置”的系统界面（WebView 没有这个界面）。

## 2. “输入数据后刷新就丢；11MB 的项目更严重”

### 原因
WebView 的 `localStorage` 有配额（不同版本大约 **5–10MB**/站点）。
旧壳还是 `file://` 加载，origin 不稳定；项目一大，`localStorage.setItem`
就会抛 `QuotaExceededError`，页面如果没捕获，看起来就是“刷新后全没了”。

另外，浏览器刷新会帮用户保留表单输入，WebView 默认不保留，
所以“只是输入了文字，刷新就空”也会发生。

### 修复（v1.2.0）
- 新壳把 `localStorage.setItem/getItem/removeItem/clear/key/length`
  代理到**原生文件存储**（每个 key 单独文件，写入后 fsync），不再受 5MB 配额限制；
- 首次启动会把旧 `localStorage` 里的数据**自动迁移**到新存储；
- 刷新页面时自动恢复表单输入（同一进程内有效；彻底退出 App 后清空，符合浏览器语义）；
- 存储数据放在 App 私有目录，卸载 App 才会清除；覆盖安装/升级保留。

### 一个重要限制（请务必转告）
WebView 的 `localStorage` 对象是浏览器内部对象，JS 只能拦截它的
**方法**，拦不住下面这种“点属性”的写法：

```js
localStorage.foo = '...';      // ← 超过 5MB 仍可能失败
localStorage['foo']            // ← 同上
```

请把页面改成方法调用（绝大多数库本来就是这么写的）：

```js
localStorage.setItem('foo', bigString);
var v = localStorage.getItem('foo');
```

或者直接用新壳提供的不限量接口：

```js
HT2A_WEB.storage.set('foo', bigString);
var v = HT2A_WEB.storage.get('foo');
```

> 11MB 的 HTML 本身不是问题（新壳按流式资源加载，不会一次性塞进内存），
> 真正受限的是“往 localStorage 里塞 11MB 数据”。现在方法调用已经不受限。

### 如果数据是“很多条记录”
更推荐用 `IndexedDB`（新壳的 HTTPS origin 下可正常使用，容量远大于 localStorage），
或者把数据存成 JSON 文件（第 1 条的保存能力），不要全部塞进 localStorage。

## 3. “原来的 HTML 有选择文件按钮，打包后点了没反应”

### 原因
`<input type="file">` 在 WebView 里不会自己弹文件选择器，
必须由宿主 App 实现 `WebChromeClient.onShowFileChooser`。旧壳没有实现，
所以点击后 WebView 只能“什么都不做”。

### 修复（v1.2.0）
- 实现 `onShowFileChooser`，支持单文件/多选、`accept` 类型；
- 用 `FileChooserParams.parseResult()` 把选择结果正确交回页面；
- 取消选择、返回键、没有文件管理器等情况都会正确结束回调，不会卡住页面；
- 同时补齐 `showOpenFilePicker()`，现代页面也能用。

### 你需要做什么
重新打包即可。页面代码不用改。
选择文件后，`FileReader` / `file.text()` 都能正常读到内容。

> `webkitdirectory`（选择整个文件夹）WebView 不支持，会退化成普通文件选择；
> 这是 Android WebView 的限制，不是打包工具的问题。

## 4. “打包成功，安装后打开白屏”

白屏有很多种，新壳现在能告诉你到底是哪一种。常见原因和对应修复：

| 原因 | 旧壳表现 | 新壳 |
|---|---|---|
| 入口在子目录（如 `dist/index.html`），旧壳只记文件名 | 404，白屏 | 记录相对路径，正确加载 |
| 页面用 `<script type="module">` | `file://` 下被 CORS 拦截，白屏 | 改用虚拟 HTTPS origin，正常 |
| 页面 `fetch('./data.json')` / IndexedDB | `file://` 下失败 | 同源 HTTPS，正常 |
| 只选了单个 HTML，CSS/JS/图片没打包 | 白屏/无样式 | 构建前警告；构建后 404 错误页会指出缺失文件 |
| 入口文件名不是 `index.html` | 白屏 | 自动扫描 HTML 候选，UI 可选择入口 |
| 页面运行时崩溃/内存过大 | 白屏 | 显示“渲染进程已结束”，可重新加载 |
| 真的加载失败 | 白屏 | 显示错误码、URL、入口路径、设备信息，可一键复制 |

### 排查步骤
1. 用新版重新打包；
2. 如果还白屏，把错误页上的文字点「复制错误」发出来（里面有 HTTP 状态/入口/设备）；
3. 打包时打开「高级 → 调试模式」，页面脚本错误会以红色横幅显示；
4. 页面依赖的资源（CSS/JS/图片/JSON）要和入口一起放在文件夹里再打包。

> 注意：Service Worker 的请求可能绕过壳的资源拦截，目前不保证可用。
> 如果页面注册了 SW，可以先用 `navigator.serviceWorker.getRegistrations()`
> 在页面里取消注册再试。

## 5. “一直构建失败，咋回事？也有对应的文件夹”

### 原因（这次最关键的发现）
旧版打包进 App 的 `aapt2` / `zipalign` 是 **非 PIE（ET_EXEC）** 的静态二进制。
Android 10 以后系统直接拒绝执行这种 ELF：

```
error: ".../libaapt2.so" has unexpected e_type: 2
```

所以引擎会“初始化失败”，构建自然一直失败。另外还有两个常见坑：

- Android 11+ 的 Scoped Storage 让 App 不能直接往 `Download/` 写文件，
  旧版在“输出 APK”这一步会失败；
- 图标特别大时 `BitmapFactory.decodeFile` 可能 OOM，导致构建中断。

### 修复（v1.2.0）
- 换成 **PIE（ET_DYN）aapt2**，即 `2.20-android-16.0.0_r4`；
- aapt2 的 `.so` 依赖（libprotobuf/absl/libc++_shared/libz/libexpat/libpng/libfmt）
  一起打包，运行时解压并通过 `LD_LIBRARY_PATH` 加载；
- **删掉 zipalign 二进制**，对齐改由纯 Kotlin 的 `ZipAligner` 完成（不再有执行问题）；
- 构建产物先写 App 私有目录（一定能安装），再用 MediaStore 发布到下载目录；
  发布失败也会提示，但不会让构建失败；
- 图标先读尺寸再降采样（最大 1024px），超大图不再 OOM；
- 应用名/版本号做 XML 转义，特殊字符不再让 aapt2 报错；
- 失败时给出中文提示 + 完整日志，不再只显示一句“构建失败”。

### 排查步骤
1. 安装新版 → 打开 App，看顶部 `ENGINE READY` 是否为绿色；
2. 如果显示 `ENGINE FAULT`，点「重新检测」，并把错误提示发出来；
3. 构建失败时，结果面板有「复制日志」，把**完整日志**发出来；
4. 日志里常见关键词：
   - `CANNOT LINK EXECUTABLE` / `library ... not found`：引擎依赖缺失（重装 App）；
   - `Permission denied`：应用分身/平行空间限制，换主空间安装；
   - `No space left`：存储空间不足；
   - `error:`：某个资源文件有问题（日志会带文件名）。
5. 如果只选了单个 HTML，请确认它引用的 CSS/JS/图片是否也需要一起打包；
   需要就改用「选择文件夹」。

## 升级与验证

1. 安装新版构建器（`app-debug.apk` 或 `app-release.apk`）；
2. **重新构建**你的项目（新壳才会进到产物里）；
3. 如果想要一份“标准答案”，安装 `tests/out/html2apk-selftest.apk`，里面有 6 个自检页：
   - 保存 JSON / 8MB localStorage / 文件选择 / ES Module / 子目录入口 / 空白页诊断。
4. 全部 PASS 说明设备和新壳工作正常；如果某项 FAIL，请把页面上的文字和机型发回来。

## 反馈问题时请附带

- 手机型号 + Android 版本；
- 构建器版本（设置/关于里可见，当前 1.2.0）；
- 产物壳版本（错误页底部有 `壳版本: 1.2.0`）；
- 构建日志（复制日志）或页面错误页（复制错误）；
- 页面是否用了：ES Module、fetch、IndexedDB、Service Worker、`showSaveFilePicker`、
  `<input type=file>`、子目录入口。

## 仍然存在的限制

- 仅支持 arm64 手机（aapt2 只有 arm64 版）；
- `localStorage.foo = ...` 这种属性赋值无法绕过 5MB 配额（请用 `setItem`）；
- Service Worker 不保证可用；
- 产物默认使用内置签名密钥，仅适合个人分发；
- 自检 APK 使用 debug 签名，仅用于验证。
